> 目标读者：已具备清华大学相关平台使用资格，希望把大模型 API 接入 DSH 的同学。<br>
> 推荐路线：获取平台 API 地址和密钥，在 DSH 中添加自定义供应商与模型，先完成普通对话测试，再按需设置推理等级、权限和插件。<br>
> 适用环境：本文主要演示 Windows 上的 DeepSeek Harness 桌面端，下文简称 DSH。<br>
> 整理时间：2026-10-15。本文按 DSH **v0.2.1-alpha.4** 官方文档核对配置说明，配图来自实际操作，不保证全部截图属于该版本。模型能力与推理参数依据官方文档整理，平台实际开放范围、使用资格和额度规则以当前平台说明为准。

先说明本文的范围：**用清华大学高性能计算平台相关入口提供的大模型 API，在本机 DSH 中调用模型。不是在超算节点上部署 DSH，也不涉及申请 GPU 节点、SSH 登录或提交计算作业。**

本文根据实际配置交流及配图整理。界面名称、可用模型和额度规则可能随版本或平台政策变化，请以自己的客户端和平台页面为准。

## 一、先了解这套搭配

这套搭配分为两部分：

- **平台侧**：提供账号、额度、大模型 API 地址和 API 密钥。本文截图中，从校方相关入口点击“点击使用”后，进入的是“并行智算云 / PARATERA”控制台。
- **DSH 侧**：作为本机的 AI 助手客户端，配置好模型接口后，可以在会话中使用模型；需要处理文件或执行命令时，再选择相应工作区和权限。

基本流程如下：

```text
登录校方相关入口，确认账号和额度
        ↓
点击使用，进入并行智算云控制台
        ↓
进入“大模型平台 → API 密钥”
        ↓
创建密钥，复制 API 地址和 API Key
        ↓
在 DSH 中添加“自定义模型 API”
        ↓
添加模型，保存供应商
        ↓
新建会话，选择该供应商下的模型并测试
```

**第一次使用，完成第二至第五节即可。**推理等级、权限调整和插件属于后续设置，不必一开始全部配置。

## 二、开始前需要准备什么

### 1. 平台账号和可用额度

需要能够登录校方提供的相关入口，并访问大模型服务。先检查：

1. 自己是否具备使用资格，是否需要先领取或激活额度。
2. 页面显示的剩余额度是否可用。
3. 是否有使用期限、适用服务范围或其他限制。

不要把截图中的领券金额、到期时间当成所有人的统一政策，也不要只看到“领券金额”就认定余额已经可以调用模型。

校方平台入口：[清华大学高性能计算平台](https://easycompute.cs.tsinghua.edu.cn/)。登录后先查看首页公告和算力券使用说明，再确认自己能否使用对应服务。账号资格、是否需要校内网或 VPN，以及额度领取、激活和有效期，请以当前页面及校方通知为准。

![清华平台首页的额度信息、“点击使用”和“账单明细”入口，个人身份信息已遮盖](/images/posts/dsh-tsinghua-hpc/11-platform-home.png)

*图 1：登录后的平台首页。左侧个人信息已遮盖；先检查额度与公告，再点击下方“点击使用”。截图中的金额和统计值只用于定位界面，不作为通用额度或计费示例。*

### 2. 安装并打开 DSH 桌面端

如果已经安装，并能打开 DSH 主界面，可以直接继续。

尚未安装的同学，请打开 [DeepSeek Harness 官方下载页面](https://www.deepseek.com/harness/)，选择适合自己操作系统的安装包。本文演示 Windows 桌面端：点击“下载 Windows 版”，下载完成后运行安装程序，按提示安装并打开 DSH。下载按钮旁的下拉菜单可切换平台；本文不展开命令行安装或源码构建。

![DeepSeek Harness 官方页面中的“下载 Windows 版”按钮和客户端界面预览](/images/posts/dsh-tsinghua-hpc/12-dsh-download.png)

*图 2：DSH 官方下载页面。下半部分是官网的产品演示，不是接入清华平台后的实际会话，也不代表默认已有平台额度。*

截至整理时，官方最新发布为 [v0.2.1-alpha.4](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.4)，发布于 2026-10-15，标记为预发布版。本文以该版本的 [官方模型配置文档](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.4/docs/user/guide/providers.zh.md) 为核对基准；截图未显示版本号，不能反推截图时安装的具体版本。下载和后续升级仍以官网提供的版本为准。

### 3. 先分清四个容易混淆的名称

| 名称 | 在哪里出现 | 用途 | 示例 |
|---|---|---|---|
| 密钥名称 / 备注 | 平台创建 API 密钥时 | 方便自己识别这把密钥 | `dsh-laptop` |
| API 密钥 / API Key | 平台生成，填入 DSH | 用于接口认证，不能用备注代替 | 自己账号生成的完整密钥 |
| Provider ID | DSH 添加自定义供应商时 | DSH 内部识别和引用这条供应商配置 | `paratera` |
| 模型 ID | DSH 模型目录中 | 指定请求实际调用哪个模型 | 从平台模型列表复制 |

**可以自己起名的是备注和 Provider ID，不是 API 密钥或模型 ID。**Provider ID 按界面要求使用小写字母开头的标识，首次可用 `paratera`；如果已经存在同名配置，应换一个未使用的 ID。

截图里也出现过 `xhr`，那是同学自己填写的 Provider ID，不是另一个必需的参数，更不需要所有人都照抄。

## 三、在平台侧获取 API 地址和密钥

### 1. 从校方入口进入服务控制台

登录 [校方平台入口](https://easycompute.cs.tsinghua.edu.cn/)，确认自己的账号和额度后，点击 **“点击使用”**。

根据示例页面，接下来会进入并行智算云控制台。如果进入的是“容器云”等页面，也不用立即创建资源，先从顶部导航切换到 **“大模型平台”**。

### 2. 打开“大模型平台 → API 密钥”

在顶部导航中选择 **“大模型平台”**，再进入 **“API 密钥”** 页面。

![并行智算云控制台中“大模型平台 → API 密钥”的入口](/images/posts/dsh-tsinghua-hpc/01-platform-api-key-entry.png)

*图 3：从顶部“大模型平台”进入 API 密钥页面。密钥处于隐藏状态，右上角平台账号已遮盖。*

### 3. 新建 API 密钥

点击 **“新建 API 密钥”**，填写“密钥名称/描述”，再点击 **“立即申请”**。

名称主要是给自己做备注，例如：

```text
dsh-laptop
```

如果不同设备各建一把密钥，可以分别命名，方便之后识别、停用或更换。

![平台“新建 API 密钥”对话框中的密钥名称或描述输入框及“立即申请”按钮](/images/posts/dsh-tsinghua-hpc/13-platform-create-key.png)

*图 4：填写方便自己识别的名称，然后点击“立即申请”。这里的名称只是备注，不是用于认证的 API Key。密钥的创建、修改和消费记录说明可参考 [官方 API 密钥管理文档](https://ai.paratera.com/document/llm/quickStart/apiKeys)。*

### 4. 复制两个关键内容

创建完成后，需要分别复制：

1. **API 地址**：页面通常标为 `API_URL / BASE_URL`。
2. **API 密钥**：刚刚生成的完整 API Key。

![API 密钥页面中 API 地址和密钥复制位置的指引](/images/posts/dsh-tsinghua-hpc/02-platform-api-url-and-key.png)

*图 5：上方箭头指向 API 地址，下方箭头指向密钥所在位置。复制密钥时使用平台提供的复制按钮，不要复制星号。*

本次材料中的地址示例为：

```text
https://llmapi.paratera.com
```

**实际填写时，以自己平台页面和接入文档给出的完整地址为准。**不要把浏览器中的控制台页面地址填进 API 地址，也不要自行添加或删除 `/v1`。本文示例截图使用的是上述地址；其他网关或其他版本应按其说明配置。

平台的 [文档入口](https://ai.paratera.com/document/llm/quickStart) 和 [API 使用快速入门](https://ai.paratera.com/document/llm/quickStart/useApi) 可用于核对。文档中的 Python 示例使用 `[hostname]/v1/`，部分请求示例使用 `/v1/chat/completions`；完整请求路径与 DSH 的基址输入框不是同一个概念。遇到 404 或路径错误时，核对客户端是否已拼接 `/v1`，不要反复盲目修改，更不要把 `/chat/completions` 当作基址填入。

API 密钥只需填入 DSH 的密钥输入框，不要发送到聊天消息里，也不要写进准备公开的教程、代码或截图中。

## 四、在 DSH 中添加供应商和模型

### 1. 打开模型设置

在 DSH 中打开 **“设置 → 模型”**，点击 **“添加模型提供商”**，选择 **“自定义模型 API”**。

![DSH 模型设置中的“添加模型提供商”按钮](/images/posts/dsh-tsinghua-hpc/03-dsh-add-provider.png)

*图 6：在“设置 → 模型”中添加模型提供商。已有的其他供应商不是本教程的前置要求，截图已裁去无关工作区和会话。*

### 2. 填写供应商信息

按以下对应关系填写：

| DSH 字段 | 填写内容 | 说明 |
|---|---|---|
| Provider ID | 例如 `paratera` | 自己起的供应商标识，遵守界面命名要求且不要重名 |
| 显示名称 | 例如“清华平台大模型” | 若界面提供此项，可填写容易辨认的名称 |
| API 地址 | 平台给出的 `API_URL / BASE_URL` | 本次截图示例见第三节 |
| API 协议 | `OpenAI Chat Completions` | 本次截图采用的协议；不是因为选择此协议就要使用 OpenAI 官方密钥 |
| API 密钥 | 平台生成的完整 API Key | 不是密钥名称，也不是 Provider ID |

![DSH 自定义模型 API 表单中的 Provider ID、API 地址、协议和密钥字段](/images/posts/dsh-tsinghua-hpc/04-dsh-custom-api-form.png)

*图 7：自定义模型 API 的主要字段。图中的浅灰色内容是输入提示，不能直接当作实际参数。*

注意，**这里是在“自定义模型 API”中配置平台提供的密钥，不是把它填进 DSH 内置的 DeepSeek 官方账号或官方 API 配置里。**

### 3. 获取并添加模型

填写地址、协议和密钥后，在 **“模型目录”** 区域点击 **“获取可用模型”**，选择自己要使用的模型。

第一次接入可以先只添加一个模型，确认能够正常对话后，再添加其他模型。不必把所有模型一次性全选。

本文示例选择是：

```text
DeepSeek-V4.1-Flash
```

这是原截图中的模型 ID，**不是对当前平台模型供应情况的保证**。如果自己的列表中没有这一项，请选平台实际提供且账号有权使用的模型；大小写、连字符和版本后缀按平台原样填写。

如果“获取可用模型”没有结果：

1. 先检查地址、密钥和协议。
2. 从控制台左侧的“模型广场”，或 API 密钥页的“在线文档”进入说明，核对可用模型。
3. 确认模型 ID 后，才通过“添加模型”手动填写，不要猜一个名称。

手动添加时，模型 ID 决定实际调用对象；显示名称只是给自己看的标签。若出现“模型 ID 不能为空”等提示，说明模型条目还没有填完整，暂时不能创建供应商。

平台模型目录：[并行智算云模型广场](https://ai.paratera.com/#/lms/model)。在这里查找目标模型，点击“查看详情”核对模型信息、能力、价格和调用限制，再按平台提供的模型 ID 配置 DSH。API 接入流程可参考 [官方快速入门](https://ai.paratera.com/document/llm/quickStart/useApi)。

![并行智算云模型广场中的模型卡片、“申请 API”和“查看详情”入口](/images/posts/dsh-tsinghua-hpc/14-platform-model-square.png)

*图 8：这是平台侧的模型广场，不是 DSH 点击“获取可用模型”后的候选列表。模型卡片用于查找和核对，不能据此认定当前密钥已获全部模型权限。*

### 4. 核对模型参数和图片输入

示例中的模型配置如下：

![示例模型的 ID、上下文窗口、最大输出 token 数和输入类型](/images/posts/dsh-tsinghua-hpc/05-dsh-model-settings.png)

*图 9：模型参数示例。图中的“图片”位于“输入类型”下，表示图片输入，不是生成图片。*

根据 DeepSeek 的 [模型与价格说明](https://api-docs.deepseek.com/quick_start/pricing/) 及 [模型元数据接口文档](https://api-docs.deepseek.com/api/list-models/)，DeepSeek-V4.1-Flash 的原厂能力如下：

| 项目 | 官方说明与本文的配置方法 |
|---|---|
| 模型版本 | `DeepSeek-V4.1-Flash` |
| 模型 ID | DeepSeek 官方接口使用 `deepseek-flash`；本文经并行智算云接入，仍填写平台返回的 `DeepSeek-V4.1-Flash`，不要擅自替换为原厂 ID |
| 显示名称 | 可填 `DeepSeek-V4.1-Flash`，仅用于界面识别 |
| 上下文窗口 | 官方为 `1M`，即 `1,048,576` token，包含输入与输出的总容量 |
| 最大输出 token 数 | 官方最高为 `384K`，即 `393,216` token；原截图中的 `32K` 是客户端配置的较低上限，不是原厂能力上限 |
| 输入类型 | 官方支持文本和图片；平台提供同等视觉能力时，在 DSH 勾选“文本”“图片” |
| 输出类型 | 文本；图片输入能力不等于图片生成能力 |
| 其他能力 | 官方支持工具调用、JSON 输出，以及思考和非思考模式；本文使用 OpenAI Chat Completions 协议 |

第一次接入可以保留截图中的 **1M 上下文、32K 输出上限**：较低的单次输出上限便于控制长回复与用量，不需要为接通模型就设到 384K。若要按原厂最大能力填写，可参考上表，但**并行智算云的网关限制可能低于原厂上限**，遇到超限应按平台模型详情调低。客户端声明不会增加实际服务能力。

图片能力同理：原厂 V4.1-Flash 支持图片，不代表每个同名中转入口都完整开放。先完成文字测试，再上传一张无敏感信息的图片测试；其他模型需分别查看其官方说明，不能把本表套用到所有模型上。

### 5. 保存供应商

确认供应商信息和模型条目完整后，点击 **“创建提供商”** 或当前版本中对应的保存按钮。

保存后回到模型设置列表，确认刚添加的供应商和模型已经出现。

## 五、新建会话，做一次最小测试

### 1. 选择刚添加的供应商下的模型

新建一个会话，点击输入框右下方的模型名称。

如果多个供应商下面都有同名模型，注意选择**刚添加的平台供应商下面的那一个**，不要只看模型名称相同就直接选。

![DSH 模型选择菜单中 paratera 分组下的 DeepSeek-V4.1-Flash 模型](/images/posts/dsh-tsinghua-hpc/15-dsh-select-provider-model.png)

*图 10：箭头指向 `paratera` 分组下的模型。截图中的勾选标记仍在上方其他供应商中，因此还需要点击箭头所指条目完成切换；不要把悬停高亮当成已经选中。*

### 2. 发送简单消息

先发送不需要读取文件或运行命令的消息，例如：

```text
请只回复“连接成功”，不要读取文件或执行命令。
```

能正常收到回复，说明本次请求的地址、密钥、模型选择等基本链路已经打通。

示例中采用的是发送 `test`，并收到了回复：

![在 DSH 中发送 test 后收到回复的示例](/images/posts/dsh-tsinghua-hpc/06-dsh-connection-test.png)

*图 11：发送 `test` 后收到回复的历史示例，本地路径已遮盖。回复中的技能和能力介绍属于该设备的具体环境，不是其他人安装后一定会有的配置；模型对自身能力的描述也不能代替工具实测。*

### 3. 接通模型，不等于所有功能都已经验证

完成文字测试后，再按自己的需要逐项测试：

- **图片输入**：上传一张无敏感信息的截图，请模型描述图中内容。
- **读取文件**：选择一个专用测试工作区，让它读取一份测试文档。
- **修改文件**：确认任务和授权范围后，让它在测试工作区新建一个简单文件。

第一轮不需要测试所有功能。先确保“能选对模型、能发送消息、能收到回复”，再扩展到文件处理或其他任务。

**本机运行 DSH 不等于模型离线运行。**让远端模型分析文件时，相关内容可能作为请求的一部分发送到平台。“仅可查看”限制的是本机操作，不代表文件内容不会外发；测试时请使用允许提交给该服务的材料。

## 六、可选：设置推理等级

### 1. 推理等级和权限不是一回事

这两类设置很容易混淆：

- **推理等级**：控制客户端向模型接口请求的推理强度，前提是模型和平台接口支持。
- **权限**：控制 DSH 是否可以读取、修改文件或执行命令。

调高权限不会把模型变得更聪明；调高推理等级也不会自动获得文件操作权限。

### 2. 如果界面已经有“推理等级”

点击输入框右下角的模型名称或当前等级，查看是否能展开 **“推理等级”** 菜单。不同版本可能先显示“模型 / 推理等级”两级入口，也可能直接展开等级列表。

![DSH 旧版模型菜单中的“推理等级”入口局部](/images/posts/dsh-tsinghua-hpc/07-dsh-reasoning-entry.png)

*图 12：旧版界面的“推理等级”入口，已裁去无关历史会话。当前界面的展开方式可能不同。*

新增截图中的菜单包含：

- `Off`
- `Low`
- `High`
- `Max`

![DSH 新增截图中的 Off、Low、High 和 Max 推理等级菜单，High 带有勾选标记](/images/posts/dsh-tsinghua-hpc/08-dsh-reasoning-levels.png)

*图 13：当前截图勾选的是 High，鼠标高亮的是 Max，并不表示已经切换到 Max。我通常使用 High，但这是个人使用习惯，不是“所有任务必须选 High”或“Max 一定最好”的结论。*

根据 DeepSeek 官方 [思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，本文所用的 **OpenAI Chat Completions 协议**对应关系如下：

| DSH 菜单 | 官方请求参数 | 含义 |
|---|---|---|
| `Off` | `thinking: {type: disabled}` | 关闭思考模式，不是一个推理强度 |
| `Low` | `thinking: {type: enabled}`，`reasoning_effort: low` | 开启思考，使用 low 档 |
| `High` | `thinking: {type: enabled}`，`reasoning_effort: high` | 开启思考，使用 high 档 |
| `Max` | `thinking: {type: enabled}`，`reasoning_effort: max` | 开启思考，使用 max 档 |

原厂默认开启思考，默认等级为 `high`。较早截图中的 `Default` 表示沿用默认值，**不等于 Off**。官方还兼容部分其他等级名，例如 `medium` 和 `xhigh` 映射到 `high`；本教程直接采用 `low / high / max`，不必额外添加这些别名。

以上是原厂参数定义，经并行智算云调用时仍以平台支持的接口为准。DSH 的菜单必须正确映射到这些参数，下一小节说明配置方法。

### 3. 如果没有“推理等级”

**先不要认为接入失败。**自定义模型可以已经正常对话，但客户端没有声明该模型可选的推理等级，因此没有显示菜单。

按 v0.2.1-alpha.4 的 [官方配置说明](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.4/docs/user/guide/providers.zh.md#推理等级)，自定义供应商可以直接在界面配置：

1. 打开 **“设置 → 模型”**，编辑自己的 `paratera` 供应商。
2. 打开 **“自定义设置”**，展开目标模型的 **“模型选项”**。
3. 打开 **“推理等级”**。初始行可能是 off、low、medium、high；按 DeepSeek 原厂说明调整为 **off、low、high、max**。
4. API 参数值分别设为：off 留空，low 为 `low`，high 为 `high`，max 为 `max`，然后保存。

**还需要注意 Off 的行为。**官方文档说明，空的 off 默认只是不发送 `reasoning_effort`；DeepSeek 是默认开启思考的模型，仅省略该字段不能关闭思考。对于这种 OpenAI 兼容网关，应在目标模型上设置 **`compat.thinkingFormat: deepseek`**，让 DSH 在 Off 时显式发送 `thinking: {type: disabled}`，其他等级发送 `thinking: {type: enabled}` 并附带相应 effort。

从设置页顶部点击 **“打开配置文件”**，先备份当前生效的 `cordis.patch.yml`。以下只是 `llm-pi-ai → config → providers → paratera → models` 中**目标模型条目的字段片段**，不是一份可覆盖整个配置文件的完整配置：

```yaml
- id: DeepSeek-V4.1-Flash
  compat:
    thinkingFormat: deepseek
  reasoningEfforts:
    off:
    low: low
    high: high
    max: max
```

把这些字段合并到现有目标模型条目，保留原有容量、输入类型、凭据引用和其他提供商配置。`paratera` 和模型 ID 都应换成自己的实际值；不要把 API 密钥写入教程或发到会话中。官方说明配置会在下一次请求时重新读取，不需要重启服务器；以设置页打开的生效配置为准，不要误改 Web 或其他 profile 的文件。

如果启用推理后出现 `developer` 角色或 `max_completion_tokens` 不被支持的错误，官方还提供了 `compat.supportsDeveloperRole: false` 和 `compat.maxTokensField: max_tokens` 兼容项；仅在平台实际需要时使用，不必为正常工作的配置强行添加。

保存后确认菜单出现，再选一个等级发送第五节的最小测试。图 13 展示菜单位置，不代表已经逐档实测平台。若需要确认发送的精确参数，请查看脱敏请求记录，避免展示认证请求头和密钥。

## 七、可选：选择合适的操作权限

输入框左下方可以调整权限。原截图中有 **“仅可查看”“工作区内修改”“完全权限”**，以及实验性的 `Auto review`。

![DSH 输入框左下方的权限选择菜单](/images/posts/dsh-tsinghua-hpc/09-dsh-permission-modes.png)

*图 14：权限菜单的位置，已裁去无关历史会话。截图选中了“完全权限”，不代表所有任务都需要这样设置。*

按任务选择即可：

| 任务 | 建议起点 |
|---|---|
| 纯文字问答、连接测试 | 保持受限权限，不需要为聊天开启完全权限 |
| 阅读和分析已有文件 | 从“仅可查看”开始 |
| 在指定项目中生成或修改文件 | 选择正确工作区后，按需使用“工作区内修改” |
| 确实要操作工作区以外的资源 | 看清具体动作和范围，再决定是否扩大授权 |

如果任务停在批准提示处，先看它准备执行什么。确认符合任务后再批准；不要把“等待授权”误判成接口故障。

有时会觉得“权限给得多，跑得快些”。更准确地说，是某些设置可能减少等待人工批准的次数，**不是提高模型服务的推理速度或算力**。具体能做什么仍取决于当前版本的权限策略。

## 八、可选：启用插件

点击侧边栏 **“插件”**，可以查看插件及开关。

我常开的两个插件是：

- **智能体团队**：界面说明为启用团队协作、团队工具、成员列表和共享任务看板。
- **自动授权审查**：界面说明为提供自动审查权限模式，由模型在工具调用前判断是否授权。

![DSH 插件页中的“智能体团队”和“自动授权审查”开关](/images/posts/dsh-tsinghua-hpc/10-dsh-plugins.png)

*图 15：插件设置示例。不同设备的开关状态可以不同，不必完全照抄。*

**接入 API、完成普通对话不需要先开启这两个插件。**有多人式任务分工或自动审查需要时，再按需启用。

自动授权审查仍是实验性功能，不等于所有操作都会安全、正确或免费。团队协作和自动审查都可能增加模型调用，启用后应关注实际用量。

### 1. 回到校方相关入口查看概览

回到 [校方平台入口](https://easycompute.cs.tsinghua.edu.cn/) 登录后的额度页面，可以查看使用概览。

- 已用卡时。

![校方平台用量概览中剩余金额、已用 token 数和账单明细入口的箭头标注](/images/posts/dsh-tsinghua-hpc/16-platform-usage.png)

## 十、常见问题

### 1. API 密钥的“名称”应该怎么填？

填一个自己能认出的备注即可，例如 `dsh-laptop`。真正用于认证的是平台生成的 API Key，不是这个名字。

### 2. Provider ID 可以随便填吗？

可以自行命名，但要遵守 DSH 界面的格式要求，并与已有供应商区分开。本文用 `paratera` 举例。

后续让 AI 检查配置时，也要使用自己实际填写的 Provider ID。不要把同学截图中的 `xhr` 当作固定值。

### 3. 点击“点击使用”后进入容器页面，怎么办？

不必先创建容器。按本次材料中的路径，从顶部导航进入“大模型平台”，再打开“API 密钥”。

### 4. 模型已经添加了，为什么还是不能回复？

按顺序检查，每次只改一项：

1. 是否选中了自定义供应商下的模型，而不是其他供应商的同名模型。
2. API 地址是否来自平台的 API 页面，而不是控制台网页地址。
3. API Key 是否完整，有没有误粘贴空格或星号。
4. API 协议、模型 ID 是否与平台说明一致。
5. 账号是否有对应模型权限，额度和密钥状态是否正常。

保留具体报错再排查，不要反复删除重建所有配置，也不要通过扩大文件权限来解决 API 认证问题。

### 5. 为什么不能上传或识别图片？

先确认模型和平台接口支持图片输入，再检查 DSH 模型配置中是否勾选“图片”。勾选只是客户端声明，不会让纯文本模型自动获得视觉能力。

### 6. 能对话，但没有推理等级菜单，正常吗？

可能正常。普通对话接通和推理等级能力声明是两个问题。按第六节核对，不要因此直接判定整个供应商配置无效。

### 7. 开启“完全权限”后，模型会更强吗？

不会。它影响的是本机操作授权，不是模型本身的能力，也不是平台推理算力。

### 8. 一定要开插件吗？

不需要。先完成最小接入，再根据任务选择插件。

### 9. DSH 显示“已完成”，可以认为任务成功了吗？

不能只看状态或模型自己的说明。聊天任务要看实际回复；文件任务要检查生成的文件；配置任务要看重载后的真实效果。

## 十一、首次接入检查清单

- [ ] 已确认自己的平台账号、使用资格和可用额度。
- [ ] 已从平台 API 页面复制地址和完整密钥。
- [ ] 在 DSH 的“自定义模型 API”中填写了对应参数。
- [ ] Provider ID 符合命名要求，且没有与其他配置重名。
- [ ] 至少添加了一个平台实际支持、账号有权调用的模型。
- [ ] 已保存供应商，并在新会话中选中了该供应商下的模型。
- [ ] 已收到一次真实的普通文本回复。
- [ ] 如需图片输入，已核对支持情况并单独测试。
- [ ] 如需推理等级，已核对平台参数，并用所选等级测试。
- [ ] 已知道从哪里查看额度、用量和账单。

完成前七项，就可以认为基本接入已经完成。推理等级、文件权限和插件可以之后按需设置。
